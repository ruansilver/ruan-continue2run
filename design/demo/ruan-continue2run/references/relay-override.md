# 放养模式（每轮固定叠加的外壳）

本会话是自动接力会话，**用户不在场**。这段文字每一轮都一样，不来自上一轮的会话内容。

## 任务入口

任务入口就是 `open` 输出里的 `context.task_entry`，它逐字来自第一条用户消息。**只认这一条**：会话中途或收尾时用户发来的其他消息，不改变任务入口，也不会被带入下一会话。

## 遇到原本要停下来问用户的节点

不要停，也不要向用户提问。按下面的方式自行判断：

1. 从需求文档和相关参考文档里推断用户的真实方向，按推断出的方向实现。
2. 结合当前项目所处的开发阶段（做加法 / 工程收口 / 最终减法）应有的取向来取舍。
3. 在可选方向中，选对项目长期最有价值的那一个。
4. **无论有没有把握，都继续往下做。** 不确定不是停下的理由；不确定性通过日志里的 `confidence` 字段留给用户事后复查。

这条只约束"任务方向判断"。它不代表遇到基础设施故障（比如创建下一会话的调用失败）时链条还能自己接上——那种情况如实记录即可。

## 做重大决策之前：先看历史决策

`open` 输出里的 `history_glob` 指向同一任务（同一 slug）的历史会话日志。做重大决策前，先读其中最近几个文件的 `decision` 记录，避免和前几轮的决策自相矛盾。

- 只读、只参考；不要把日志内容整段复制进上下文。
- 真正需要长期有效的决策，应该由任务本身落到需求文档或项目文档里，日志只负责追溯。

## 记录关键决策

每次触发上面的自行判断（或做出其他重要选择），立刻记一条：

```
python3 <skill_dir>/scripts/relay.py decision --log <log_path> \
  --node "遇到的问题/节点" --choice "最终选择的方向" \
  --basis "依据的文档或线索" --confidence "把握程度（如 high / medium / low）"
```

只记事实。琐碎的、不影响方向的选择不用记。

## 收尾

任务做到告一段落时，直接调用 `finish`（见 SKILL.md 第 4 步）。**不要自己判断"任务是不是已经全部完成、还要不要接力"**——这不是本 Skill 的职责，收尾就是收尾。
